## Interactive features

- Responsive navigation for desktop, tablet and mobile.
- Light and dark themes, saved in the visitor's browser.
- Animated role headline, metric counters, reveal-on-scroll and subtle card interactions.
- Project category filters and interactive work-focus tabs.
- Public GitHub repository loading with search, language filters, sorting and browser-side cache.
- **Published website links open directly in a new browser tab.** No iframe or embedded preview dialog is used.
- A repository is treated as published when it has a valid GitHub `homepage` URL or GitHub Pages is enabled (`has_pages: true`). Otherwise, the card links to source code only.
- Quick navigation palette using `Ctrl + K` / `⌘ + K`.
- Keyboard focus states and reduced-motion support.

## Personal photo

The profile image is loaded from **`assets/mahmoud.jpg`** and reused in the site header, the hero area, and the profile summary. To replace the photograph, put another image in the `assets` directory using the same filename. No initials or placeholder avatar are required.

## Run locally

```bash
python -m http.server 8000
```

Then open `http://localhost:8000`.

## Publish on GitHub Pages

Upload the **contents** of this folder to the root of the `Mahmoud_Hamed` repository. Keep `index.html`, `styles.css`, `script.js`, and `assets/` at the same level. Then open **Settings → Pages**, publish from the intended branch and `/ (root)` folder, and wait for deployment to complete.

## Add links to published projects

For each project repository, enable GitHub Pages in **Settings → Pages**, or put its actual public demo URL in **About → Website**. The portfolio opens that destination in a new tab. A repository without a published URL is shown as source code only; the portfolio does not invent a demo URL.

See [DEPLOYMENT_GUIDE.md](DEPLOYMENT_GUIDE.md) and [PROJECT_PREVIEW_GUIDE.md](PROJECT_PREVIEW_GUIDE.md) for setup details.
